PHP Issues Emergency Patches for PHP2Shell RCE Flaws

Two critical Remote Code Execution (RCE) vulnerabilities affect the core PHP runtime across all versions from PHP 5.4 up to 8.5. Immediate patching and server restarts are required.

Read Source Article ↗ Back to Overview ←

⚠️ High Risk Threat: PHP2Shell

CVSS 9.2 (Critical)

On October 21, 2026, the PHP development team released emergency security updates for two core runtime flaws that allow unauthenticated attackers to achieve Remote Code Execution (RCE) or read sensitive process memory on target servers.

Because these flaws exist within the PHP engine itself rather than application-level code (like WordPress or Laravel), even a basic, static PHP endpoint can be susceptible to compromise. Active exploit attempts have been detected globally.

Tracked Vulnerabilities

CVE-2026-109618

RCE via OOM Memory Corruption

Triggered when a request forces PHP to run out of memory. During process termination, incomplete internal data structures are handled as valid during cleanup, causing memory corruption that attackers can leverage for remote execution.

CVE-2026-109619

RCE via Stale Global State

A Use-After-Free (CWE-416) condition where internal request pointers persist across requests within long-running worker processes. Subsequent requests handled by the same worker can read or manipulate freed memory state.

Affected Versions & Patches

Upstream patches have been released for actively supported PHP branches. Check your server's runtime version immediately:

PHP Branch Status First Fixed Version
PHP 8.5 Vulnerable below 8.5.12 8.5.12
PHP 8.4 Vulnerable below 8.4.27 8.4.27
PHP 8.3 Vulnerable below 8.3.36 8.3.36
PHP 8.2 Vulnerable below 8.2.35 8.2.35
PHP 8.1 & earlier (EOL) Vulnerable (No upstream patch) Requires Vendor / ELS / Source Backport

Auditing with php2shell-check

You can use php2shell-check in local mode to verify if your active local runtime or server CLI build is vulnerable:

# Run local CLI environment audit
bash php2shell-check.sh -m local

# Run remote HTTP inspection for exposed PHP signatures
bash php2shell-check.sh -m web -s -u https://your-domain.com

Recommended Remediation Steps

  1. Update System Packages: Upgrade your PHP binaries via system package managers (e.g. apt upgrade php, dnf update php) or pull updated Docker image tags.
  2. Restart Web Processing Workers: Ensure you restart php-fpm, apache2, nginx, or any container workers so updated binaries take effect in memory.
  3. Enable WAF Protections: If immediate patching is delayed, activate Web Application Firewall rules (e.g. Cloudflare / AWS WAF) to block suspicious multipart payloads.
  4. Audit Log Entries: Watch for HTTP 500 errors, unusual Out-Of-Memory logs, oversized PHPSESSID cookies, or unexpected worker restarts.
